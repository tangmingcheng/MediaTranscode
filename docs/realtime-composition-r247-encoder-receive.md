# r247：编码成功取包区间随AU传递

r246仅证明当前canonical wrapper构造至scheduler观察很短。当前EncodedVideoOutputFanoutNode::retainPacketHeader会重新构造canonical wrapper，因此不能把该时间自动当作encoder原始出包时刻；需要补齐跨fanout保留的证据。

复用r246中GStreamer逐buffer/逐element边界观测原则及既有mediaAccessUnitObservationNow：在VideoEncodeNode实际receivePacket调用前后采steady时间，仅将成功返回且时间有效的区间以固定大小值附于canonical AU。成功返回的packet先解析原有opaque lineage，再把该次调用区间与它一起发布。fanout克隆同一个AU时保留区间，输入canonicalizer和音频canonicalizer明确标记未观测。State关闭或时钟区间无效均为缺失，不干预媒体结果。

scheduler现有first/late诊断输出同identity/generation/sequence的receive begin/end，不增加日志频率、历史ring、线程或公共参数，不修改FFmpeg依赖。该区间不是GPU执行时间；NVENC receive内部也可能submit frame与阻塞lock bitstream。它首先区分成功取包调用内耗时与更早/更晚耗时；不宣称覆盖先前EAGAIN、encoder输入等待或sendFrame的全部时间，也不将一次成功调用直接归因于GPU。

接口变更必须更新所有canonical AU构造点，fanout需保留观测。固定inline optional区间随AU生命周期持有，无动态观测分配，跨线程发布后不可变。共享Windows/RKMPP实现，仍先Windows实流。待双审、全量Release和原规格复验。
两位独立审查者实际读取8文件及全仓4个构造调用后均限定PASS；没有改变原媒体结果或多包映射。源码冻结，全量Release会话99961进行中，尚无运行通过结论。
