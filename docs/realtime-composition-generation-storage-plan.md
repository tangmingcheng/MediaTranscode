## 证据与预算域

MediaProtocolOutputGenerationData当前initial及purge/reset使用普通make_unique，session由两个consumer普通make_shared；旧Data销毁前先创建新Data，因此容量必须覆盖二者同时存活。Data内的optional prepared transaction/materializer属于实际sizeof，间接动态对象有各自backing，不重复计入。

MediaProtocolOutputGenerationState已有prepare-before-state-change/reset事务边界。现有MediaBudgetMemoryResource、MediaOwnedMemoryAllocation、shared allocation geometry probe及固定容量storage可复用，不新建allocator算法。PreparationMemoryResource注释限定preparation预算域；运行期固定control不得挪入该域。

现有DatagramTransportPlanBuffer依赖activation才创建network池，晚于节点初始Data，不直接提前替代。最终planner应按实际封闭拓扑/节点类型及ABI geometry生成固定control存储产品，在MediaRealtimeNetworkResourceLedgerPlanner/FinalGraphResourceLedgerCompiler的实际账本中归属清楚，runtime compilation在factory创建consumer前建立独立固定Network资源实例。
